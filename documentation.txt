## 3. API Endpoints

### GET /api/v1/notifications
Retrieves all notifications in the system, ordered by date (newest first).

**Example:**
```bash
curl -X GET http://localhost:3000/api/v1/notifications
```

### POST /api/v1/notifications
Creates a new notification using the unified `notify(to, from, content)` method.
This endpoint returns the full list of all notifications after creation.

**Parameters:**
- `to`: Recipient (userId as number OR email as string)
- `from`: Sender name or identifier
- `content`: Notification payload (can be string or object)

**Request Body Examples:**

#### 1. Simple Text Notification
```json
{
  "userId": 1,
  "from": "System",
  "message": "Your account has been updated"
}
```

#### 2. New Message Notification
```json
{
  "userId": 1,

  "type": "new_message",
  "metadata": {
    "messageId": "123",
    "messagePreview": "I am interested in your profile..."
  }
}
```

## 4. Enhanced Features

### Automatic URL Generation
The system automatically generates URLs for email templates based on notification type:
- **new_message**: messageUrl, loginUrl
- **application_status**: applicationUrl, loginUrl
- **job_alert**: jobUrl, loginUrl
- **job_status**: dashboardUrl
- **verification**: verificationUrl, verificationLink
- **welcome**: loginUrl, dashboardUrl

### User Preference Management
- Automatically creates default preferences for new users
- Respects user email/push/SMS preferences
- Supports daily digest mode
- Implements 5-minute delay for unread notifications before sending email

### Smart User Resolution
- Accept userId (number) or email (string) as recipient
- Automatic user lookup and validation
- Returns detailed error if user not found

### Comprehensive Response
The notify method returns:
```json
{
  "success": true,
  "userId": 1,
  "userEmail": "user@example.com",
  "type": "new_message",
  "title": "New Message Received",
  "message": "You have a new message from John Doe",
  "notificationId": 42,
  "emailQueued": false,
  "preferences": {
    "emailEnabled": true,
    "pushEnabled": true,
    "dailyDigest": false
  },
  "metadata": { ... }
}
```

## 5. Testing with cURL

### Send a Message Notification
```bash
curl -X POST http://localhost:3000/api/v1/notifications \
-H "Content-Type: application/json" \
-d "{\"userId\": 1, \"from\": \"John Doe\", \"type\": \"new_message\", \"metadata\": {\"messagePreview\": \"Hello!\"}}"
```

### Send Using Email Instead of UserId
```bash
curl -X POST http://localhost:3000/api/v1/notifications \
-H "Content-Type: application/json" \
-d "{\"email\": \"user@example.com\", \"from\": \"System\", \"type\": \"job_alert\", \"metadata\": {\"jobTitle\": \"Developer\"}}"
```

### Get All Notifications
```bash
curl -X GET http://localhost:3000/api/v1/notifications
```
